## 3. 环境事实（下一轮先读）

1. 会话是 **full access**，审批关闭；`dsh-delete-guard` 仍拦截提及 C: 的命令，这是有意的 C 盘边界。
2. **工作区被打 Low 完整性标签**。在其中构建的可执行文件是 Low 进程，写不了 `%LOCALAPPDATA%\Khor\runtime`，
   CLI 会 `拒绝访问 (os error 5)`。因此 CLI/进程/网络/GUI 的验证一律用工作区外构建：
   ```powershell
   $env:CARGO_TARGET_DIR='F:\Temp\khor-target'
   cargo build --locked -p khor-cli      # 或 -p khor-gui / cargo test -p khor-node --test <t>
   ```
   库单测仍可用工作区内的 `.cache/target`。
3. **ConPTY 输出在本会话环境里读不到**：宿主 `last.txt` 永远为空、`ring` 不写入；直接 `portable-pty` 读
   `cmd /c echo` 只收到控制台的 `\x1b[6n` 初始化序列，拿不到程序输出（取 reader 早于/晚于 spawn 都一样）。
   这是 W3 T5、W4 两条 replay、W5 终端面板共同的未解项。
4. **GUI 构建**：Vite 7 拒绝含 `#` 的工程根，用无 `#` 的 worktree（本轮 `F:\Temp\khor-gui`，分支 `w5-gui-check`）。
   本机**没有 npm**，只有 node + pnpm；GUI 有 npm 提升才成立的幻影依赖（`@shikijs/langs`、`@shikijs/themes`、`hast`），
   所以 `pnpm install` 必须加 `--node-linker=hoisted --shamefully-hoist`，脚本用
   `node scripts/generate.mjs`、`node_modules/.bin/tsc.cmd --noEmit`、`node_modules/.bin/vite.cmd build` 直接跑，
   不要走 `pnpm run`（它会调用 npm）。
5. 网络可用：curl 200、DNS/TCP 通。
